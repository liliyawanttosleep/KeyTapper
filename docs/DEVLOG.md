# KeyTapper Development Log and Current State

> 中文版： [DEVLOG.zh-CN.md](DEVLOG.zh-CN.md)

Last updated: 2026-11-12 · Current version: 0.3

## 1. What this is

A keyboard auto-clicker for Windows. It is a single-file Python program (`keytapper.py`) with a
tkinter UI; keys are sent to the foreground window through Win32 `SendInput`. Pillow is the only
third-party dependency. The UI is in Chinese.

## 2. Features implemented so far

| Area | Feature |
| --- | --- |
| Keys | Single keys, combinations (Ctrl / Shift / Alt / Win + any key), modifier-only keys, left / right / middle mouse buttons |
| Sequence | Multi-step loops (A → B → C → back to A); each step has a repeat count (1–999) and an optional wait of its own |
| Timing | Default interval (ms / s / min, minimum 1 ms), start delay, hold time, random jitter |
| Stopping | Manual, after a set duration, after a set number of rounds |
| Hotkey | Global start/stop hotkey, F6 by default, rebindable to any key or combination |
| Games | Requests administrator rights at launch; send mode is either "game compatible" (scan codes) or "normal" (virtual-key codes) |
| Presets | Save / save as / delete / switch named presets; export to `.json`, import someone else's |
| Feedback | Status pill, tiles for key count / rounds / run time, progress bar, start and stop beeps |
| Other | Always on top, remembers window position, single instance, settings auto-save, crashes written to `error.log` |

## 3. History

### v0.1 — basic clicker (2026-11-12)
- First version in tkinter + ctypes, light theme, standard library only.
- The core model was a list of steps from the start: one step is a plain clicker, several steps are a loop.
- Key capture polls `GetAsyncKeyState` rather than using Tk key events.
  Reason: with a Chinese IME active, Tk reports key code 229 (VK_PROCESSKEY) and the real key is lost.
- The global hotkey is polled the same way, every 25 ms. No `RegisterHotKey`, no keyboard hook.

### v0.2 — working inside games, presets (2026-11-12)
- **Problem**: the user reported that nothing happened in their game and the hotkey could not stop
  the loop there, while everything worked outside the game.
- **Cause**: the game runs elevated. Windows UIPI blocks input from a lower-integrity process to a
  higher-integrity window, and `GetAsyncKeyState` in the lower-integrity process cannot see keys
  typed into that window either.
- **Fix**: self-elevate at launch with `ShellExecuteW(..., "runas", ...)`. If the prompt is declined
  the app continues unelevated and shows a warning in the UI.
- Sending now defaults to `KEYEVENTF_SCANCODE`; the "normal" mode is kept as a fallback.
- Added presets: save, switch, import, export. Imported data goes through `sanitize_preset`.
- The user confirmed this version works in their game.

### v0.3 — new UI, icon, more features (2026-11-12)
- Dark theme. Rounded cards, buttons and fields are bitmaps drawn with Pillow and stretched as
  nine-patch ttk image elements.
- New icon: a keycap with an endless-loop legend and tap ripples, generated by `tools/make_icon.py`.
- Added: per-step repeat count, duplicate step, beeps, stat tiles, progress bar, single instance,
  window position memory.
- Alert / confirm / input dialogs are now custom (`MsgDialog`). Only the file pickers are still native.

### v0.3 release (2026-11-12)
- Packaged as a GitHub repository: README, MIT licence, requirements, example preset, shortcut script.
- Added `tests/selftest.py` and this log.

## 4. Code layout

Everything lives in `keytapper.py`, divided by comment banners, top to bottom:

| Section | Contents |
| --- | --- |
| Key sending | ctypes structs, `KEY_NAMES`, `combo_text`, `is_down`, `send_key` |
| Engine | `Tapper`: background thread that loops over a job and sends keys, with precise waits on `perf_counter` |
| Config | `DEFAULT_CFG`, `PRESET_KEYS`, `sanitize_preset`, `load_cfg`, `ensure_admin` |
| Colours and drawing | Colour constants, `dark_titlebar`, `Gfx` (draws the bitmaps), `BigButton` (gradient main button) |
| Dialogs | `Dialog` base class, `MsgDialog`, `StepDialog` (key capture) |
| Main window | `App`: styles, layout, sequence editing, presets, start/stop, the `_tick` refresh loop |
| Entry point | `already_running` (mutex), `main` |

### Data flow

```
UI inputs ──_collect()──> self.cfg ──build_job()──> job ──> Tapper.start(job)
                              │
                              └──_save()──> config.json
```

- One step in `cfg["steps"]`: `{"mods": [17, 16], "key": 65, "times": 1, "interval": null, "unit": "毫秒"}`
  - `mods` and `key` are Windows virtual-key codes; mouse buttons are 1 / 2 / 4.
  - `interval: null` means "use the default interval".
  - Unit values are the Chinese strings used as keys of `GAP_UNITS` and `DUR_UNITS`
    (`毫秒` ms, `秒` s, `分钟` min, `小时` h). They are stored in config and preset files as is.
- `build_job()` flattens the steps into the list the engine runs (repeat counts are expanded here).
  Each item is `{"mods": [...], "key": vk, "gap_ms": milliseconds}`. One "round" is one full pass
  over the flattened list.
- Export file format: `{"app": "KeyTapper", "version": 1, "name": "...", "preset": {the PRESET_KEYS fields}}`.
  See `examples/abc-loop.json`.
- Hotkey, always-on-top, sound, send mode and window position are per-machine settings and are
  not part of a preset.

## 5. Pitfalls already hit (read before changing code)

1. **ttk image elements need `padding=0`.** Otherwise the element uses `border` as inner padding
   and every widget grows.
2. **Button styles need `width=0`.** The clam theme gives TButton a default minimum width of 11 characters.
3. **The bitmaps have no alpha channel.** The area outside the rounded corners is pre-filled with
   the parent's background colour, so a widget placed on a different background needs bitmaps
   generated for that colour (the `bg` argument of `nine()`).
4. **Every size goes through `self.S()` or `Gfx.px()`.** The process is DPI aware; hard-coded pixel
   values shrink on high-DPI displays.
5. **An `element_create` name can only be created once per Tk interpreter**, so there can be only
   one `App` per process.
6. **While running, all inputs are disabled and focus moves to the root window.** Otherwise, when
   the clicker itself is the foreground window, the keys it sends type into its own fields or
   press its own buttons.
7. **The hotkey must not equal a key in the sequence**, or the injected key is seen by the hotkey
   poll and the clicker stops itself. `start()` checks this.
8. **Adding a setting**: add it to `DEFAULT_CFG`; if it belongs to a preset, also add it to
   `PRESET_KEYS` and handle it in `sanitize_preset`, `_collect` and `_apply_preset`. Older
   `config.json` files missing the field fall back to the default.
9. **Keep `.bat` and `.ps1` files ASCII-only**, or they break under the default code page of
   Chinese Windows.

## 6. How to verify

```bash
pip install -r requirements.txt
python tests/selftest.py
```

The self-test runs the engine with F13 / F14 / F15, keys that normally have nothing bound to them
(both send modes, a time limit, a round limit, stopping during the countdown), checks preset export,
import and rejection of invalid files, then opens the real window and runs a round-limited job.
It uses a config in a temporary directory, never touches your `config.json`, and does not need
administrator rights. Note that it does send real key events and the window appears briefly.

Not covered by the self-test, so check by hand: the elevation flow, key capture, the F6 hotkey,
and behaviour inside an actual game.

## 7. Known limitations

- Not packaged as a standalone exe; users need Python and Pillow.
- Games with kernel-level anti-cheat block `SendInput`. This cannot be solved from user mode.
- Left and right modifiers are not distinguished, nor are main Enter and numpad Enter.
- Mouse buttons click at the current cursor position only; no coordinates.
- The UI is Chinese only.
- Import and export use the native file dialogs, which are light and do not match the theme.
- Below roughly 10 ms the real rate is limited by the hold time and the OS scheduler.

## 8. What could come next

Roughly by value. None of these has been started:

1. Package with PyInstaller, declare `requireAdministrator` in the manifest, publish on GitHub Releases.
2. UI localisation (at least English), with the UI strings gathered into one table.
3. Mouse clicks at given coordinates, mouse movement.
4. Record a real input sequence and replay it (macros).
5. Send keys only while a chosen window is in the foreground.
6. Separate start and stop hotkeys; a "click while the hotkey is held" mode.
7. Minimise to the system tray.
8. Split `keytapper.py` into `engine` / `config` / `ui` modules and add unit tests for the engine and config.

## 9. Conventions for whoever continues

- After a change, run `python tests/selftest.py` and check by hand what it does not cover.
- If the UI changes, update `docs/screenshot.png`.
- Append an entry to section 3 of this file, update sections 2, 7 and 8 to match reality, and keep
  the Chinese version in sync.
- `config.json` and `*.json` in the repository root are the user's personal data. They are excluded
  by `.gitignore`; do not commit them.
